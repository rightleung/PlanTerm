# PlanTerm v1.1 Public Release Master Plan

## Release Intent

v1.1 is the next productization release after the current integrated `miniso-2026` case. It makes the local FP&A workbench safe to show publicly in three ways:

1. The dashboard has a bounded responsive shell with no accidental page clipping or unexplained horizontal scrollbar.
2. The user interface is first-class in English (`en`), Simplified Chinese (`zh-CN`) and Traditional Chinese (`zh-TW`).
3. A public ticker import can normalize usable reported financial statements for LSE, A-shares, Hong Kong stocks and US stocks without pretending that public data is internal company data.

The first import slice is a stateless preview. It does not create or persist a case, does not mutate `data/cases/miniso-2026`, and does not replace the deterministic MINISO example. The existing FP&A calculations, provenance labels and RMB 0.01 million reconciliation tolerance remain unchanged.

## Current Source of Truth and Versioning Note

The working tree is clean at commit `d7709e5` (`chore: remove obsolete planning documents`). Repository metadata is behind the implemented UI/documentation: `pyproject.toml`, `src/config.py` and `web/package-lock.json` say `0.2.0`; tags exist through `v0.2.1`; README, Roadmap, release evidence and the footer describe v0.3/v0.5/v1.0 work. v1.1 planning must not rewrite history or silently relabel the current case. During implementation, expose one additive release identifier (for example `1.1.0-rc.1`) through a dedicated release/version contract, and keep a compatibility note for existing `0.2.x`/`v0.2.1` clients until the release owner deliberately updates package metadata and UI labels.

## Goals

- Remove shell-level overflow and card misalignment at supported desktop, tablet and mobile viewports.
- Centralize all user-facing UI strings behind a typed locale catalog with English fallback.
- Provide an allowlisted, exchange-aware public financial-data ingestion boundary for LSE, A-shares, Hong Kong and US listings.
- Make statement periods, currency, units, source, retrieval time and as-of/disclosure information explicit in API and UI.
- Keep reported actuals (`public_reported`) separate from synthetic allocations/plans (`synthetic_allocation`, `synthetic_plan`) and calculated values.
- Preserve existing FP&A semantics, filters, planning horizon, session-only previews, Excel structure and reconciliation tolerances.
- Produce deterministic evidence suitable for a public release review, while making live provider checks optional and clearly marked.

## Non-Goals

- No ERP, bank, HRIS, payroll, internal forecast, private-company or authenticated data integration.
- No persistence, accounts, multi-user collaboration, database, cloud deployment or automatic release publication.
- No arbitrary URL fetch, credential storage, browser automation, unapproved scraping or bypass of provider terms.
- No FX conversion or cross-currency consolidation in the first import slice; native source currency and unit are shown instead.
- No automatic creation of an FP&A case from a ticker in v1.1. Case creation/mapping is a follow-on increment.
- No claim that MINISO-only data, synthetic category allocations, illustrative cash, workforce or action records are publishable internal-company data.
- No localized Excel labels in v1.1. Workbook content and sheet names remain English; localized workbook export is an explicit v1.2 candidate.

## Release Slices

### Slice 1: Responsive shell and overflow hardening

**Scope**

- Establish a single shell contract: `body` owns no horizontal overflow; `.app-shell` and `.content` are width-constrained; every flex/grid child that may shrink has `min-width: 0`.
- Use a centered content container with `width: min(100% - 2 * var(--gutter), var(--content-max))`, stable gutters and `max-width` rather than child widths that can exceed the viewport.
- Use card grids with `repeat(auto-fit, minmax(min(100%, 260px), 1fr))` for KPI/scenario cards and `minmax(0, 1fr)` for two-column panels.
- Make `.table-scroll` the sole horizontal-overflow owner for wide tables. It must have `max-width: 100%`, `overflow-x: auto`, keyboard focus affordance and an accessible label. Tables may keep a content minimum inside that wrapper but may never enlarge the page.
- Make the planning dialog `width: min(1200px, calc(100vw - 2 * var(--dialog-gutter)))`, `max-height: calc(100dvh - 2 * var(--dialog-gutter))`; dialog content owns vertical scroll and matrix owns two-axis scroll.
- Add responsive stacking at 960px, 720px and 480px (document exact behavior in CSS), including hero metadata, filter controls, export row, footer and form grids.

**Files/components to change**

- `web/src/index.css`: shell/container/grid/overflow contract, breakpoints, table/dialog rules and focus styles.
- `web/src/App.tsx`: semantic landmarks, stable wrapper classes, locale switcher slot, and no layout-affecting inline widths.
- `web/src/features/dashboard/FilterBar.tsx`, `KpiGrid.tsx`, `MonthlyTrendChart.tsx`, `VarianceTable.tsx`, `PvmBridge.tsx`, `ProfitBridge.tsx`, `ManagementInsights.tsx`, `DataProvenance.tsx`.
- `web/src/features/governance/DecisionLog.tsx`, `ProvenancePanel.tsx`; `web/src/features/operating-plan/*.tsx`; `web/src/features/planning-inputs/PlanningInputs.tsx`: table/dialog wrappers and accessible labels.
- `web/e2e/dashboard.spec.mjs`: viewport and overflow assertions.

**Acceptance**

- At every viewport in the matrix below, `document.documentElement.scrollWidth === document.documentElement.clientWidth` when no dialog is open.
- No visible right-edge clipping; cards in each row share a left/right grid edge; two-column panels either align or stack at the documented breakpoint.
- Wide tables scroll only inside their labeled wrapper; keyboard users can reach the wrapper and dialog controls.
- Opening the planning dialog never changes page width, traps focus, or clips the close/footer controls.

### Slice 2: Three-locale UI foundation

**Architecture**

- Add `web/src/i18n/index.ts` with `Locale = 'en' | 'zh-CN' | 'zh-TW'`, typed `TranslationKey`, `I18nProvider`, `useI18n`, `t(key, vars)`, `formatNumber`, `formatCurrency`, `formatDate` and `formatPlural`.

- Add an API-label registry (`web/src/i18n/apiLabels.ts`) for known metric, driver, plan-variant, market, provenance and status codes. Unknown API labels remain visible verbatim with a provenance/source indicator.
- Use `Intl.NumberFormat`/`Intl.DateTimeFormat` with locale-specific defaults; currency formatting accepts the API currency code and never converts values. Plural messages use `Intl.PluralRules` or ICU-style `one`/`other` variants. Dates are parsed as ISO dates and displayed in the selected locale; period keys remain stable IDs.
- Persist `planterm.locale` in `localStorage`; initial selection is stored locale, then browser language mapping (`zh-CN`/`zh-SG` to `zh-CN`, `zh-TW`/`zh-HK` to `zh-TW`, all else `en`). Invalid values reset to English. Switching is immediate and does not refetch data.
- Add a labeled locale switcher in the header with keyboard support, visible focus, `aria-label`, and `aria-live` announcement for the changed locale. CJK text must not overflow controls or table cells.

**Files/components to change**

- `web/src/i18n/**` (new), `web/src/main.tsx` (provider), `web/src/App.tsx` (switcher and provider use), `web/src/api/client.ts` (typed API error code handling), `web/src/types/planning.ts` (locale/import types).
- `web/package.json` and `web/package-lock.json`: add a dev-only TypeScript unit-test runner compatible with the existing Vite toolchain (for example Vitest) and a reproducible `test:i18n` script; this is test infrastructure, not a runtime i18n dependency.
- Every component under `web/src/features/**`, `web/src/components/**` and `web/src/export/managementPack.ts` must remove user-facing hardcoded UI strings from JSX. Excel labels stay English in v1.1 and are explicitly documented as deferred.
- `web/e2e/dashboard.spec.mjs` plus locale unit tests cover switching, persistence, fallback, formatting and accessibility.

**Acceptance**

- A locale audit finds no user-facing literal in rendered JSX except approved data values and the English export contract.
- All three locales render the complete primary dashboard, planning dialog, operating decision sections, errors, empty states and provenance disclosures without overlap.
- Refreshing preserves the selected locale; an intentionally missing key renders English and records a warning without breaking the page.

### Slice 3: Safe public ticker ingestion preview

**First-slice product decision**

`POST /api/v1/public-import/preview` returns a stateless `PublicImportPreview`. It accepts one exchange/ticker pair and returns normalized annual/quarterly reported statements plus readiness and provenance. It does not create a `Case`, write disk, or cache user content beyond bounded in-memory provider response caching. The UI renders a separate Public data preview panel. A preview can be inspected beside the existing dashboard but cannot silently overwrite `miniso-2026`.

**Request contract**

```json
{
  "exchange": "LSE | A_SHARE | HKEX | US",
  "ticker": "string",
  "venue": "SSE | SZSE | BSE (required only for A_SHARE)",
  "periods": "annual | quarterly | both (default both)",
  "include_profile": false
}
```

Validation is strict: `exchange` is an enum; `venue` is required only for `A_SHARE` and must be one of `SSE`, `SZSE` or `BSE`; non-A-share requests must omit it; ticker is trimmed, bounded (1-24 ASCII characters before exchange-specific normalization), and contains no URL/control characters; `periods` is an enum. A bare six-digit A-share code without a venue is rejected with an ambiguity error.

**Response contract**

```json
{
  "preview_id": "opaque non-secret id",
  "request": {"exchange":"US","ticker":"AAPL","venue":null,"normalized_symbol":"AAPL","periods":"both"},
  "company": {"name":"Apple Inc.","currency":"USD","country":"US"},
  "statements": [
    {"period_end":"2025-09-27","period_type":"annual","fiscal_year":2025,"fiscal_quarter":null,"is_flow":true,"currency":"USD","unit":"USD millions","unit_scale":"millions","values":{"revenue":...},"source":{"provider":"yfinance","url":"...","retrieved_at":"...","as_of":"...","filing_date":"..."}}
  ],
  "mapping": {"dashboard_ready":false,"reason":"native_currency_not_RMB_or_planning_assumptions_missing"},
  "disclosures": ["Public reported data only; not internal company data.","Provider data may be delayed, restated or incomplete."],
  "provenance": {"provider":"yfinance","source_urls":["..."],"retrieved_at":"...","as_of":"...","normalization_version":"public-import-v1"}
}
```

Values are finite numbers or null; statement rows identify whether a metric is a flow or stock, preserve native currency and scale, normalize period dates to ISO `YYYY-MM-DD`, and retain provider/source/filing provenance. Missing required statement fields result in a typed error or a row-level `missing` status, never a fabricated zero.

**Provider design**

- Define `PublicFinancialDataProvider` in `src/services/public_import/providers.py` with `provider_id`, `supports(exchange, venue=None)`, `normalize_symbol(exchange, ticker, venue=None)`, and bounded `fetch(request) -> ProviderResult`.
- The default mapping is yfinance for US, HKEX and LSE symbols (US `AAPL`, HK `0005.HK` after zero-padding, LSE `VOD.L`), and optional AKShare for explicitly mapped A-share venues. SSE/SZSE must each have a tested mapping; BSE may be advertised only when an approved provider capability exists, otherwise it returns `unsupported_exchange` or `dependency_missing` and is not presented as available. A-share provider code may use the relevant RiskLens date/key normalization ideas but must not copy its application or bypass provider terms.
- Optional dependencies are isolated extras (`public-data-yfinance`, `public-data-akshare`). The API reports `dependency_missing` with installation guidance when an explicitly selected provider is unavailable; it never imports optional libraries at module import time.
- Provider calls run in a bounded thread pool behind an asyncio semaphore because pandas/provider clients are blocking. Per-provider timeout is 8 seconds, total request deadline 12 seconds. Retry at most twice with exponential backoff and jitter for connection/timeouts/5xx; do not retry invalid ticker, unsupported exchange, malformed data or rate limits unless `Retry-After` is honored.
- Positive cache: in-memory LRU, maximum 256 normalized request keys, 15-minute TTL. Negative cache: typed failures for 60 seconds (rate-limit 15 seconds). Single-flight coalescing prevents duplicate cold misses. Per-provider rate limit defaults to one upstream request per second and is configurable only through server settings.

**Normalization and validation**

- Exchange and, for A-shares, venue disambiguation are mandatory and recorded in the normalized symbol. US class shares map `BRK.B` to `BRK-B`; HK codes are four digits with `.HK`; LSE tickers carry `.L`; A-shares carry an explicit `SSE`/`SZSE`/`BSE` provider mapping and remain six digits.
- Annual and quarterly statements are normalized to common metric IDs (`revenue`, `gross_profit`, `operating_profit`, `operating_expense`, `cost_of_sales`, `cash`, `total_assets`, `total_liabilities`, `operating_cf`) with a source field map. Flow and stock semantics, fiscal year/quarter, period end and filing date are explicit. Duplicate dates are deduplicated deterministically; inconsistent statement dates produce `period_inconsistent`.
- Currency is an ISO code from provider metadata or a validated exchange default; missing/ambiguous currency is `currency_missing`. Units are normalized to a declared scale (`native`, `thousands`, `millions`) without silent FX conversion. The preview displays native currency/units and is not compared numerically to RMB case values.
- Error taxonomy maps to existing `{error,error_type,details}`: `invalid_exchange`, `invalid_venue`, `invalid_ticker`, `ambiguous_ticker`, `unsupported_exchange`, `dependency_missing`, `no_data`, `malformed_upstream`, `period_inconsistent`, `currency_missing`, `rate_limited`, `provider_timeout`, `provider_unavailable`, `validation_error`, `internal_server_error`. Error details contain no credentials, request headers, query strings or stack traces.

**Dashboard flow and boundary**

The preview panel consumes `PublicImportPreview` directly and shows reported actual statement rows, native currency/unit and provenance. The existing `DashboardResponse` remains the deterministic MINISO contract. A follow-on adapter may project a validated preview into a read-only dashboard projection, but only with an explicit `preview_id` and a visible `public_reported`/native-currency banner. Synthetic planning assumptions are generated or edited in a separate session object and never merged into reported rows. Creating a persisted/imported case is deferred until a later release with an explicit schema and migration review.

**Fixtures and live smoke tests**

- Add deterministic provider fixtures for one representative symbol per market: `LSE`, `A_SHARE` (SSE and/or SZSE mapping), `HKEX`, and `US`; fixture payloads include annual and quarterly statements, currency, scale, period dates and source metadata.
- Unit/contract tests run with no network and cover normalization, field mapping, missing data, malformed values, duplicate periods, currency/unit handling, cache/rate-limit behavior and every error type.
- Optional live smoke tests run only when `PLANTERM_LIVE_PUBLIC_DATA=1` and explicit allowlisted tickers are configured. They are non-blocking in ordinary CI and report provider/as-of evidence. Separate outage tests force provider exceptions; unsupported ticker tests must return a typed 4xx without fallback to an unrelated company.

## Risks and Controls

| Risk | Control / release gate |
|---|---|
| CSS child minimums create page overflow again | DOM width assertion at every viewport; only `.table-scroll` and `.matrix-scroll` may scroll horizontally; visual screenshot review. |
| CJK strings overflow or lose meaning | Complete locale fixture, fallback telemetry, CJK viewport tests, no truncation of disclosures, accessible labels checked. |
| Provider returns restated/incomplete/mismatched statements | Strict period/field/currency validation, row-level missing status, source/as-of disclosure, no fabricated zeros. |
| A-share symbol maps to wrong listing | Exchange is required; explicit SSE/SZSE/BSE map; ambiguous bare symbols rejected. |
| Blocking upstream call exhausts server | Bounded executor/semaphore, deadline, single-flight, cache, rate limits and timeout metrics. |
| Provider terms prohibit a method | Allowlisted clients only, optional dependencies, no credentialed or unapproved scraping, release-owner terms review. |
| Public data is mistaken for internal planning data | Persistent banners/provenance; separate preview type; synthetic inputs cannot overwrite reported rows. |
| Version metadata drift confuses users/clients | Additive release contract and compatibility note; update labels only with owner-approved release metadata change. |
| Existing `miniso-2026` clients break | Keep all current routes and response fields; additive endpoint/types; contract tests against current fixtures; rollback by disabling import route/UI flag. |

## Data and Legal Disclosures

- Public reported data is sourced from provider APIs or approved public endpoints and may be delayed, restated, incomplete or mapped differently under local accounting standards.
- The product does not provide investment, legal, accounting, credit-rating or lending advice.
- Public import does not expose MINISO internal data. The MINISO case remains a bounded public-data case with synthetic allocations and planning assumptions.
- Source URLs, provider IDs, retrieval timestamps, as-of dates, filing dates and normalization version are included in preview evidence.
- No credentials, cookies, proxy secrets, arbitrary URLs or raw upstream response headers are accepted from or returned to the browser.
- Live calls are opt-in for smoke tests and must honor provider rate limits, terms and licensing. A provider outage is a normal typed state, not a reason to substitute guessed data.

### Leader reconciliation gate

The leader reconciles worker reports in this order: (1) reject any out-of-scope edits or missing routing evidence, (2) resolve interface conflicts between `PublicImportPreview`, locale types and UI shell, (3) verify current `miniso-2026` contract/tolerance invariants, (4) require Reviewer D to re-run failed gates after fixes, and (5) return a single pass/block record to the root. The root retains final authorization for changes, release labels, live smoke enablement, tagging and publication.

## Rollback and Compatibility

- All v1.1 routes and UI entry points are additive. A server feature flag (default off for live providers until release-owner approval) can disable `/api/v1/public-import/preview`; the deterministic case remains available.
- Keep existing route paths, query parameters, response fields and planning payloads unchanged. New locale fields/types are optional for old clients; old clients continue receiving English server labels.
- If shell or i18n regressions appear, revert only the v1.1 frontend commit or disable the locale switcher; no case files or planning seeds change.
- If a provider is unstable or terms change, disable that provider mapping, preserve fixture-backed preview behavior, and return `provider_unavailable`; do not fall back to unrelated symbols or synthesize reported values.
- Existing `miniso-2026` users retain the seeded Base/Upside/Downside flow, session-only previews, Excel export and all current provenance semantics.
